# Bestax Accessibility Conformance Report

International Edition

(Based on VPAT® Version 2.5Rev)

**Name of Product/Version:** `@allxsmith/bestax-bulma` 5.x, the release on npm at the report
date, and the bestax.io site

**Report Date:** November 2026

**Product Description:** Bestax is a React component library for the Bulma CSS framework,
published to npm as `@allxsmith/bestax-bulma`, and bestax.io is its documentation site, with
live examples of the components.

**Contact Information:** Open an issue with the
[Accessibility Issue template](https://github.com/allxsmith/bestax/issues/new?template=accessibility-issue.md),
or ask on [Discord](https://discord.gg/zehJrQGtKu).

**Notes:**

- **Scope.** This report covers the components in `@allxsmith/bestax-bulma`, rendered the way
  their API pages and Storybook stories show them, and bestax.io: the docs, the blog and the live
  examples on their pages. An app built with Bestax isn't covered. WCAG conformance is defined
  for whole pages, so an app's conformance is its own, and the components can't settle the
  criteria that belong to a page, such as its title, its language or a way to skip its
  navigation. The [accessibility statement](./index.md) lists what an app still owns.
- **Two parts per row.** Each row's remarks give the components' part and the site's part, and
  its conformance level is the lower of the two.
- **Only Web applies.** The template splits each WCAG row into Web, Electronic Docs, Software,
  Closed and Authoring Tool. Bestax is web content: a library that renders HTML in a browser,
  and a website. It ships no non-web documents, has no closed functionality, and isn't an
  authoring tool, since it has no editor and the content an app builds with it is the app's.
  So each row answers for Web, and Electronic Docs, Software, Closed and Authoring Tool are Not
  Applicable for every row.
- **Known gaps.** Remarks cite the open issues behind the gaps they describe. The open issues
  with the
  [`accessibility` label](https://github.com/allxsmith/bestax/issues?q=is%3Aissue%20state%3Aopen%20label%3Aaccessibility)
  are the full, up-to-date list, including a few, such as development warnings, that no single
  criterion covers. A fix that would change what existing apps rely on waits for the next
  major version and carries the `next-major` label, and the remarks say so.
- **Self-assessed.** The maintainer wrote this report. It hasn't been audited by a third party.
- **Kept current.** A fix that closes or opens a known gap updates its rows, and the report date
  above, in the same change. The rows describe the code on `main`, which reaches npm with the
  next release.

**Evaluation Methods Used:**

- [axe-core](https://github.com/dequelabs/axe-core) 4.14, through Storybook's accessibility
  addon, on every story of every component, in Chromium, in the light and the dark scheme, on
  every pull request. A violation fails the pull request unless the story's exemption names the
  open issue that tracks it, or the reason axe is wrong there. axe's contrast rule is off for
  the stories until [#2188] is settled.
- axe-core 4.14 on every page of the built bestax.io site, in both color modes, including the live
  examples a page shows (one inside a closed tab or a closed `<details>` isn't checked), after
  each change reaches `main`, with the same rule for exemptions. The site's
  contrast check is exempted until [#2215] is settled.
- Unit tests (Vitest, in jsdom) for the components' keyboard interaction and ARIA roles, states
  and properties, and, for the components those settings change, how they draw in forced colors
  and with reduced motion.
- A simulated screen reader ([Guidepup Virtual Screen Reader](https://github.com/guidepup/virtual-screen-reader))
  for what TreeView announces.
- Accessibility audits of the components and the site, whose findings are the issues with the
  `accessibility` label.
- Not done yet: tests with NVDA, JAWS, VoiceOver or TalkBack, in a real Windows contrast theme
  rather than Chromium's emulation of one, or in Firefox or Safari. Text resizing, text spacing
  and reflow are judged from the CSS (Bulma sizes text in `rem` and `em`) rather than tested on
  every component.

## Terms

The terms used in the Conformance Level information are defined as follows:

- **Supports:** The functionality of the product has at least one method that meets the
  criterion without known defects or meets with equivalent facilitation.
- **Partially Supports:** Some functionality of the product does not meet the criterion.
- **Does Not Support:** The majority of product functionality does not meet the criterion.
- **Not Applicable:** The criterion is not relevant to the product.
- **Not Evaluated:** The product has not been evaluated against the criterion. This can only be
  used in WCAG Level AAA criteria.

## WCAG 2.x Report

Tables 1 and 2 also document conformance with:

- EN 301 549: Clause 9 (Web), Clauses 10.1 to 10.4 (Non-web documents), Clauses 11.1 to 11.4 and
  11.8.2 (Software), and Clauses 12.1.2 and 12.2.4 (Documentation).
- Revised Section 508: Chapter 5, 501.1 Scope and 504.2 Content Creation or Editing, and
  Chapter 6, 602.3 Electronic Support Documentation.

For Bestax only the web clauses among those apply: EN 301 549 Clause 9, 12.1.2 and 12.2.4, and
Revised Section 508 501.1 and 602.3. The non-web document, software and authoring tool clauses
are Not Applicable (see Notes). A criterion added in WCAG 2.1 also applies to EN 301 549, but not
to the Revised Section 508 standards, which take in WCAG 2.0. A criterion added in WCAG 2.2 applies to neither. Each such
row says so.

When reporting on conformance with the WCAG 2.x Success Criteria, they are scoped for full pages,
complete processes, and accessibility-supported ways of using technology as documented in the
[WCAG 2.1 Conformance Requirements](https://www.w3.org/TR/WCAG21/#conformance-reqs).
